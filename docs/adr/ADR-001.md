# ADR-001: Using an AI assistant for the Lab 5 Firebase code

**Date:** 2026-11-11  **Author:** Tahir Emre Çiçek  **Milestone:** Lab 5
**Tool and model used:** Claude Code + Claude Opus 5.5

## Context
I had to connect the Study Notes app to my own Firebase project and complete the TODOs in
Parts 1–6 (Note model, AuthRepository, NotesRepository, NotesScreen, security rules, FCM).
The starter Android project also did not build with my Flutter version (3.47), because its
Gradle, Android Gradle Plugin and Kotlin versions were below Flutter's minimum.

## Prompt
Here is the Lab 5 PDF and the starter project. Guide me step by step and write the code
for each TODO so that test/lab05_test.dart passes, without changing the test file.
Keep the existing comments and TODO lines in the files.

## Result
The AI wrote the code for note.dart, auth_repository.dart, notes_repository.dart,
notes_screen.dart, messaging_service.dart, firestore.rules and own_test.dart.
It also raised Gradle 8.12 → 8.14, AGP 8.9.1 → 8.11.1 and Kotlin 2.1.0 → 2.2.20 so the
app builds. I committed each part separately (see the commits "Part 1" … "Part 7").

## Rejected suggestion(s) — at least one
- The Flutter build output suggested the flag `--android-skip-build-dependency-validation`
  to get past the version errors. I did not use it: it only hides the version check, and the
  build could still fail later. Raising the versions fixes the real cause.
- The AI first removed the `// TODO` comments and `ignore_for_file` lines from the starter
  files. I asked it to keep all the original comments so the files stay close to the starter
  and the TAs can see where each part was completed.

## Verification
- `flutter test`: all 15 provided tests and my 4 own tests pass (+20).
- `flutter analyze`: no issues.
- Manual test on the emulator: create account, sign in, add a note, empty title shows
  "A title is required.", swipe to delete, sign out.
- Rules Playground: another user's notes → Denied, my own notes → Allowed.
- A test push message arrived in the notification tray.

## What I learned
Security has to be enforced in Firestore rules, not only in the app, because the app's
checks can be bypassed. Fakes like FakeFirebaseFirestore and MockFirebaseAuth make it
possible to test Firebase code without a real project, which is why CI can run the tests.
